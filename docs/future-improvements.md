# 追加機能検討（P3-03）

このドキュメントは、Phase 1〜2 の基盤が安定した後に検討する改善テーマをまとめたものです。  
現時点では確定した開発計画ではなく、優先順位・前提条件とともに整理したロードマップ候補です。

---

## 1. 重複チェック精度向上

### 現状の課題

現在の重複防止は Drive ファイル ID の一致のみで判定しています。以下のケースで二重登録が発生する可能性があります。

- 同一の証憑を別のデバイスで再撮影した場合（異なるファイルが生成される）
- ファイルを削除後に再アップロードした場合（Drive ファイル ID が変わる）

### 改善案

| 案 | 手法 | 精度 | 実装コスト |
|----|------|------|----------|
| A | 画像ハッシュ（ピクセル比較）による重複検知 | 高 | 高 |
| B | OCR 抽出結果の組み合わせ（利用日+支払先名+金額）でのソフトマッチ | 中 | 中 |
| C | Gemini API に重複可能性の判定を委譲 | 中〜高 | 低 |

### 推奨アプローチ

**案 B**（利用日 + 支払先名 + 合計金額の一致）を先行実装し、疑わしい場合は NEEDS_REVIEW 扱いにする。確定的な重複とは区別して「要確認（重複候補）」として台帳に記録し、人が最終判断する設計とする。

### 前提条件

- Phase 1〜2 が本番稼働し、台帳データが十分に蓄積されていること
- 誤検知（正常ファイルを重複と判定）のリスクを受け入れられる設計にすること

## 2. 会計システム連携

### 現状

スプレッドシートへの登録で処理が完結しており、会計システムへの自動連携は行っていません。

### 連携候補

| 対象システム | 連携手段 | 備考 |
|------------|---------|------|
| freee | freee API | REST API、OAuth 認証が必要 |
| 弥生会計 | CSV インポート | 所定フォーマットへの変換が必要 |
| マネーフォワード クラウド会計 | API または CSV | API は有料プランのみ対応の場合あり |
| 社内会計システム | 個別対応 | 要件定義から必要 |

### 実装方針（案）

1. スプレッドシートを「中間データストア」として維持する（外部連携が変わっても再利用できる）
2. 連携は別 GAS スクリプト（または別トリガー）として実装し、OCR バッチと分離する
3. 連携済みフラグを台帳に追加して二重送信を防止する

### 前提条件

- 利用する会計システムの API 仕様・認証方法を事前に調査すること
- 経費申請フローとの整合性（承認前に連携するか否か）を整理すること

## 3. その他の拡張候補

| テーマ | 概要 | 優先度 |
|-------|------|-------|
| 通貨変換 | 外貨レシートの金額を円換算して台帳に記録 | 低 |
| 複数申請者対応 | CONFIG.APPLICANT_NAME を動的に切り替える運用サポート | 低 |
| HEIC 変換の安定化 | HEIC が Gemini で読み取れないケースへの対処（JPEG 事前変換） | 中 |
| 処理量のダッシュボード | スプレッドシートの集計シートで月次処理件数・エラー率を可視化 | 低 |
| Gemini モデルの切り替え | 将来のモデルアップグレードに対応した設定変更手順の整備 | 低 |

---

## 4. 優先順位まとめ

| 順位 | テーマ | 理由 |
|------|-------|------|
| 1 | HEIC 変換の安定化 | 実運用で最も発生しやすい問題 |
| 2 | 重複チェック精度向上（案 B） | 運用コストの削減効果が高い |
| 3 | 会計システム連携（freee） | 利用者の手作業を最も削減できる |
| 4 | 複数申請者対応 | チーム利用時に必要 |
| 5 | その他 | 要望に応じて対応 |
