## 1. 障害一次切り分けフロー

問題が発生したらまず以下のフローで原因を特定してください。

```
証憑が処理されない・登録が正しくない
           │
           ▼
    01_取込 フォルダにファイルが残っているか？
           │
      Yes ─┼─ No（別フォルダに移動済み）
           │               │
           ▼               ▼
   GAS トリガーは動いているか？   04_エラー に移動していないか？
           │                           │
      No ──┼──Yes              Yes ─────┼──── No（02 or 03 にある）
           │        │                  │               │
           ▼        ▼                  ▼               ▼
    [A] トリガー  GAS 実行ログを      処理ログで       台帳の内容を
      再設定       確認する           エラー内容確認    確認・修正する
               （手順 5 参照）      （手順 3 参照）   （月次運用手順書参照）
```

## 2. ファイルが処理されない

### 症状
`01_取込` フォルダにファイルを入れたが、しばらく経っても移動されない。

### 確認事項と対処

| 確認事項 | 確認場所 | 対処 |
|---------|---------|------|
| タイムトリガーが設定されているか | GAS エディタ → トリガー | トリガーを追加する（セットアップ手順書 手順 8 参照） |
| ファイル形式が対応しているか | ファイルの拡張子 | JPEG / PNG / HEIC / WebP のみ対応。PDF は非対応 |
| ファイル名に既にプレフィックスが付いているか | ファイル名 | `yyyymmdd-` で始まるファイルはスキップされる。リネームして再投入 |
| GAS のエラーが発生していないか | GAS エディタ → 実行数 | エラー内容を確認して対処（[手順 5](#5-gas-の実行エラー) 参照） |

## 3. スプレッドシートに登録されない

### 症状
ファイルは `04_エラー` フォルダに移動したが、台帳に行が追加されていない。

### 確認事項と対処

1. 「処理ログ」シートを開き、該当ファイル名の行を探す
2. D 列（メッセージ）でエラーの内容を確認する

| エラーメッセージ | 原因 | 対処 |
|---------------|------|------|
| `GEMINI_API_KEY がスクリプトプロパティに設定されていません` | API キー未設定 | スクリプトプロパティに `GEMINI_API_KEY` を設定する（セットアップ手順書 手順 7 参照） |
| `Gemini API エラー (HTTP 400)` | プロンプトまたはモデル名の誤り | `CONFIG.GEMINI_MODEL` の値を確認する |
| `Gemini API エラー (HTTP 403)` | API キーが無効 | Google AI Studio で API キーを再発行して設定し直す |
| `Gemini API エラー (HTTP 429)` | API クォータ超過 | しばらく待ってから `01_取込` に戻して再処理する |
| `シートが見つかりません:` | シート名の不一致 | `CONFIG.SHEET_NAME` または `CONFIG.LOG_SHEET_NAME` とスプレッドシートのシート名を一致させる |
| `Gemini レスポンスの JSON パースに失敗しました` | Gemini の返答が JSON でない | ファイルを `01_取込` に戻して再試行する（画像品質を確認する） |

## 4. OCR の精度が低い / 要確認フラグが多い

### 症状
台帳の Y 列（要確認フラグ）が `TRUE` になる行が多い。Z 列の理由が「合計金額が取得できませんでした」等。

### 対処

| 要確認理由 | 主な原因 | 対処 |
|----------|---------|------|
| 合計金額が取得できませんでした | 画像が不鮮明、または合計欄が写っていない | 鮮明な画像を再撮影して再投入 |
| 利用日・発行日が取得できませんでした | 日付欄が隠れている・切れている | 手動で日付を入力する |
| 支払先名が取得できませんでした | ロゴのみで店舗名テキストがない | 手動で支払先名を入力する |
| 合計金額と税内訳の合計が一致しません | レシートの印字が薄い・読み取り誤り | 元の証憑と照合して金額を修正する |
| 書類種別が判定できませんでした | 様式が特殊・破損 | 書類種別を手動で修正する |

### 画像品質の改善ポイント

- 証憑全体が写るように撮影する
- 十分な明るさの場所で撮影する（逆光・影に注意）
- なるべく平らに広げて撮影する（折り目・湾曲に注意）
- HEIC 形式（iPhone の標準形式）は対応しているが、JPEG 変換してから投入するとより安定する

## 5. GAS の実行エラー

### エラーログの確認手順

1. GAS エディタを開く
2. 左側メニューの「実行数」（≡ アイコン）をクリックする
3. エラーが発生した実行行をクリックしてスタックトレースを確認する

### よくある GAS エラー

| エラー内容 | 原因 | 対処 |
|----------|------|------|
| `Exception: You do not have permission to call DriveApp.getFolderById` | Drive へのアクセス権限が未承認 | GAS エディタから `main` を手動実行し、権限を許可する |
| `Exception: Spreadsheet not found` | `SPREADSHEET_ID` が正しくない | `Config.gs` の `SPREADSHEET_ID` を確認する |
| `Exception: Folder not found` | フォルダ ID が正しくない | `Config.gs` の各フォルダ ID を確認する |
| `Exceeded maximum execution time` | 1 回の実行が 6 分を超えた | `MAX_FILES_PER_RUN` を減らす（デフォルト 10 → 5 など） |
| `Service invoked too many times in a short time` | API 呼び出し頻度の制限 | トリガーの実行間隔を長くする（10 分 → 30 分など） |

## 6. ログの確認方法

### 処理ログシート（スプレッドシート）

スプレッドシートの「処理ログ」シートで全処理結果を確認できます。

| 列 | フィールド | 内容 |
|----|---------|------|
| A | 処理日時 | 処理が実行された日時 |
| B | ファイル名 | 処理対象のファイル名 |
| C | 処理結果 | `成功` / `要確認` / `エラー` |
| D | メッセージ | エラー内容・要確認理由（詳細） |
| E | ファイルID | Drive ファイル ID（重複防止・再処理の特定に使用） |

### GAS 実行ログ（Logger）

リアルタイムのデバッグログは GAS エディタの「実行数」で確認できます。`[INFO]` / `[ERROR]` のプレフィックスでフィルタリングできます。

## 7. 再処理手順

### 通常の再処理（自動）

1. `04_エラー` フォルダから対象ファイルを `01_取込` フォルダへ移動する
2. 次回のタイムトリガー実行（最大 10 分後）で自動処理される

> ファイル名が `yyyymmdd-エラー-` で始まっている場合、`DriveService` がスキップします。`yyyymmdd-エラー-` プレフィックスを除去してから `01_取込` に移動してください。

### 手動対応による完了処理

エラーを自動再処理せず手動でスプレッドシートに入力した場合：

1. 入力完了後、`04_エラー` フォルダのファイルを `02_処理済み` フォルダへ移動する
2. ファイル名の `yyyymmdd-エラー-` プレフィックスはそのまま残す（手動対応の証跡）

### 重複検知されてスキップされた場合

1. 「処理ログ」シートの E 列（ファイルID）で同一 ID が既に登録されているか確認する
2. 台帳に登録済みであれば重複のため処理不要
3. 台帳に未登録であれば管理者に報告して対処を依頼する

詳細な再処理フローは [`docs/error-handling.md`](./error-handling.md#6-再処理手順) を参照してください。
